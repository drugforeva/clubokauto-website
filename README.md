# Сохрано (@Sohrano_bot)

Телеграм-бот на Telegram Business API: сохраняет переписку владельца, ловит удалённые
и отредактированные сообщения собеседников и сразу присылает уведомление с исходным
текстом и вложениями.

Стек: Python 3.12, aiogram 3.x, PostgreSQL, Redis, SQLAlchemy 2 (async), Alembic, structlog.

## Что умеет

- **Архив переписки.** Каждое сообщение из бизнес-чатов попадает в базу с автором,
  типом, текстом и метаданными вложений (13 типов контента, неизвестный тип — как
  `unknown`, а не потеря).
- **Уведомления об удалении.** Собеседник удалил — владелец получает текст, тип и сводку
  по вложениям. Удалённое не вырезается из архива, а получает метку.
- **История правок.** Первая правка сохраняет и исходник, и новую версию; все версии
  видны на отдельном экране.
- **История и поиск.** Листание по 8 записей, фильтры по тексту, автору, типу, датам,
  только удалённые, только правленные. На PostgreSQL — полнотекстовый поиск
  (GIN + `to_tsvector('russian', ...)`), на sqlite — `ILIKE`.
- **Статистика.** Сколько сохранено, сколько удалено и отредактировано, разбивка по
  типам, топ диалогов, объём вложений.
- **Экспорт** в TXT, CSV, JSON и HTML — с текущими фильтрами и в поясе владельца.
- **Настройки.** Уведомления об удалениях/правках, свои сообщения, сохранение и скачивание
  вложений, часовой пояс, срок хранения (0/7/30/90/180/365 дней).
- **Админка.** Пользователи, их сообщения, вложения, версии, удаления, рассылка,
  uptime и счётчики ошибок.

## Требования

- Python 3.12 (код использует `datetime.UTC` и `X | Y` в аннотациях).
- PostgreSQL 16 и Redis 7 (в docker-compose уже есть).
- **Telegram Premium** у владельца — без него раздела Telegram Business нет.
- В BotFather у бота включён Business Mode: `/mybots` -> Bot Settings -> Business Mode -> Turn on.
- На телефоне владельца: Настройки -> Telegram для бизнеса -> Чат-боты -> `@Sohrano_bot`.

## Быстрый старт (Docker)

```bash
cp .env.example .env
# в .env: BOT_TOKEN от BotFather и BOT_ADMIN_IDS — ваш Telegram ID
docker compose up -d --build
docker compose logs -f bot
```

Контейнер сам ждёт готовности базы, применяет миграции (`alembic upgrade head`) и
запускает поллинг.

## Запуск без Docker

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # впишите BOT_TOKEN и BOT_ADMIN_IDS
alembic upgrade head
python -m app
```

Для проверки без PostgreSQL и Redis есть режим на sqlite и памяти:

```bash
pip install -r requirements-dev.txt
BOT_TOKEN=... python run_local.py
```

`run_local.py` сам создаёт таблицы в `sohrano_local.db`, так что Alembic не нужен.

## Миграции

```bash
alembic upgrade head                        # применить
alembic revision --autogenerate -m "описание"  # новая ревизия
alembic downgrade -1                        # откатить
```

GIN-индекс для поиска создаётся только на PostgreSQL: выражение в индексе совпадает
с выражением в запросе символ в символ, иначе планировщик индекс просто не возьмёт.

## Тесты и линтер

```bash
pip install -r requirements-dev.txt
pytest -q          # 76 тестов, sqlite в памяти, без сети
ruff check .
python smoke_e2e.py  # оффлайн-прогон всего сценария
```

Покрыто: разбор типов сообщений, сохранение и идемпотентность, версии правок,
удаления (включая сообщения вне архива), фильтры поиска и изоляцию по владельцу,
все четыре формата экспорта, работу со временем и экранирование HTML.

## Грабли, которые учтены в коде

1. **Нет Premium — нет бизнес-апдейтов.** Бот при этом работает, но архив пуст; `/help`
   объясняет, что именно нужно включить.
2. **`business_message` приходит только после подключения.** Старую переписку
   выгрузить невозможно, поэтому удаление неизвестного сообщения даёт честное
   уведомление «сообщение вне архива».
3. **`allowed_updates` нужно указывать явно.** Бизнес-апдейты не входят в набор по
   умолчанию — список задан в `app/bot.py`.
4. **`date` приходит целым числом.** Всё прогоняется через `as_datetime()`, в базе
   хранится naive UTC, пояс применяется только на выводе.
5. **HTML ломает отправку.** Любой чужой текст идёт через `escape()`, длинные
   уведомления режутся по лимитам 4096 и 1024 символа.
6. **Имя файла пришло от собеседника.** `sanitize_filename()` убирает `../` и нулевые
   байты до склейки с путём.
7. **Bot API не отдаёт файлы больше 20 МБ.** Метаданные сохраняются всегда, скачивание
   — опция, лимит настраивается.
8. **Блокировка бота не должна ронять рассылку.** `TelegramForbiddenError` помечает
   пользователя как заблокировавшего и рассылка идёт дальше.
9. **Каждый запрос ограничен `owner_id`.** Архив одного владельца не виден другому;
   на это есть отдельный тест.

## Ограничения

- Архивируются только сообщения бизнес-чатов после подключения.
- Самоуничтожающиеся сообщения и секретные чаты Bot API недоступны.
- Экспорт ограничен 5000 строками на файл.
- Один процесс поллинга: второй экземпляр с тем же токеном получит конфликт от Telegram.

## Фото на один просмотр и исчезающие медиа

Коротко: через Bot API сохранить такое фото **нельзя**, и это ограничение
самого Telegram, а не бота.

- В Bot API нет ни одного поля для медиа с таймером или режимом «один просмотр»:
  нет `ttl_seconds`, нет `view_once`. Файл такого сообщения боту не выдают.
- Сохраняют такие фото только юзерботы на MTProto (Telethon, Pyrogram), которые работают
  от имени живого аккаунта. Это другая архитектура и прямой риск бана аккаунта.

Что бот делает вместо этого:

1. `_marks()` в `app/business/extractor.py` проверяет шесть возможных признаков
   одноразового медиа (`ttl_seconds`, `view_once`, `self_destruct_time` и т.д.).
   Проверка идёт через `getattr`, поэтому новое поле Bot API подхватится без правок.
2. Если признак нашёлся, `CaptureService` пишет в лог `capture.ephemeral` и **скачивает
   файл немедленно**, даже когда автозагрузка выключена: `file_id` у исчезающего
   сообщения умирает вместе с ним.
3. В карточке и в списке такое сообщение помечается 🔥, фото под спойлером — 🙈.

### Как проверить самому

```bash
docker compose logs -f bot | grep -i ephemeral
```

Попросите кого-нибудь прислать фото с таймером в бизнес-чат. Если в логах тишина
и сообщение не появилось в `/history` — значит, Telegram его боту не отдал.
Сообщение в логах означает обратное: формат появился и файл уже сохранён
в `MEDIA_ROOT`.

### Что работает точно

Обычное фото, которое отправитель удалил через секунду после отправки, архив
сохраняет полностью — вместе с файлом, если в `/settings` включено
«Скачивать вложения». Именно этот сценарий большинство людей и имеет в виду,
когда говорит про «фото на один раз».

### Спасение по ответу

Одноразовое фото Bot API боту не отдаёт, но у Telegram есть щель: когда вы
**отвечаете** на сообщение, оригинал приезжает в `reply_to_message` целиком —
вместе с `file_id` вложения. Бот этим пользуется.

1. Собеседник прислал фото (в том числе одноразовое).
2. Вы отвечаете на него любым текстом (свайп → «Ответить»).
3. Бот достаёт вложение из цитаты, дописывает сообщение в архив, скачивает
   файл (даже если автозагрузка выключена) и присылает его вам в чат с ботом
   карточкой «🛟 Спасено из ответа».

Что важно знать:

* Приём гарантированно спасает **любое сообщение, которого нет в архиве**:
  например, присланное до подключения бота или потерянное во время перезапуска.
* Для настоящих одноразовых медиа всё зависит от того, положит ли Telegram
  файл в цитату. Гарантий в документации нет — проверяется опытом:

  ```bash
  docker compose logs -f bot | grep -iE "rescue|ephemeral"
  ```

  Строка `rescue.reply` или `rescue.ephemeral_reply` значит, что файл в цитате был
  и его удалось вытащить.
* Ответ на сообщение, которое уже в архиве, ничего не присылает — спама не будет.
  Цитата без вложения просто молча дописывается в архив.
* Если Telegram прислал цитату без номера сообщения (`message_id = 0`, так
  бывает у исчезающих), файл всё равно приедет вам в чат — просто без
  записи в архиве: такую строку нечем отличить от следующей такой же.
* Тумблер «🛟 Доставать медиа из ответов» живёт в `/settings` и включён по
  умолчанию.
